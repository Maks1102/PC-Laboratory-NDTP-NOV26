# Модели деталей «ПК-Лаборатории» — экспорт из веб-сцены

Каждая деталь выгружена из `src/lib/three/simulator-scene.ts` (геометрия повторена 1-в-1 тем же кодом, что и в сцене).

## Форматы

| Папка/файлы | Назначение |
|---|---|
| `*.fbx` | Запрошенный FBX 7.4 **бинарный** (открывается Blender, Godot 4.3+, Maya) |
| `*.glb` | glTF 2.0 binary — **рекомендуется для Godot**: материалы PBR (цвет, металличность, шероховатость, emissive LED, прозрачность стекла) переносятся точнее всего |
| `gltf/*.gltf` | Те же модели в glTF JSON (с полными PBR-материалами), если нужно читать/править вручную |

Для одного и того же ассета файлы имеют одинаковое имя: `mobo.fbx = mobo.glb = gltf/mobo.gltf`.

## Импорт в Godot 4

1. **Предпочитайте `.glb`/`gltf`** — нативный формат Godot, материалы переносятся без потерь. FBX в Godot 4.3+ импортируется через встроенный ufbx, но emissive/прозрачность у FBX могут потребовать доработки в инспекторе.
2. **Ориентация**: ось Y вверх (как в three.js/godot). Каждая модель **стоит на y=0** (низ bbox в origin) и центрирована по XZ — можно ставить `position = (x, 0, z)` без подгонки.
3. **Масштаб**: координаты — «игровые юниты» веб-сцены (корпус = 18 юнитов, CPU = 1.7). Для точного повторения раскладки веб-версии оставляйте 1:1; если нужны «метры» — импорт-скейл 0.1 (корпус станет 1.8 м).
4. **Иерархия**: внутри файла меши плоские, имена `<part>_<n>` (например `case_45` — вентилятор). Группируйте в Godot как удобно.
5. Наклейки (SSD «NVMe SSD», БП «750 Вт») — без текстур: это светлые плоскости, наденьте свою текстуру в Godot.

## Как это сделано

- `scripts/export-parts.mjs` — строит каждую деталь теми же вызовами Three.js, что и сцена, экспортирует glTF + OBJ/MTL
- `scripts/convert-fbx.sh` — OBJ → FBX через assimp 5.4.3
- `scripts/convert-glb.py` — glTF → GLB через trimesh
- Проверка: габариты и количество треугольников в FBX совпадают с исходником 1-в-1 (например, корпус: 8 × 18.06 × 16.68 и 2328 фейсов до/после конвертации)
